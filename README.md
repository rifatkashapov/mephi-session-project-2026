1.1 Для сетевого интерфейса enp0s3 была настроена динамическая конфигурация IPv4 по протоколу DHCP. Настройка выполнена средствами NetworkManager с помощью утилиты nmcli. Для соединения был установлен метод ipv4.method auto, после чего сетевое соединение было перезапущено. В результате интерфейс автоматически получил IP-адрес, шлюз и параметры DNS.
1.2 Имя хоста системы было изменено на mephi-2026.domain.local с помощью утилиты hostnamectl.
1.3 Для проверки сетевой связности с внешней сетью была выполнена отправка четырёх ICMP Echo Request пакетов на публичный DNS-сервер Google с IP-адресом 8.8.8.8. Результат выполнения команды сохранён в файл ping.out. Получение ответов от удалённого узла подтверждает наличие сетевой связности виртуальной машины с внешней сетью.

2.1 Выполнено обновление установленных пакетов дистрибутива РЕД ОС 8 с использованием пакетного менеджера DNF. Командой dnf upgrade были загружены и установлены доступные обновления из подключённых репозиториев. После обновления выполнена повторная проверка наличия новых версий пакетов.
2.2 С помощью пакетного менеджера DNF из настроенных репозиториев были установлены веб-сервер nginx и пакет libcap-ng-utils, содержащий утилиты для работы с механизмом Linux capabilities. Наличие установленных пакетов проверено командой rpm -q.
2.3 Бинарный RPM-пакет tcpdump был загружен в каталог /tmp с помощью команды dnf download tcpdump. После загрузки пакет был установлен напрямую средствами RPM командой rpm -Uvh. Корректность установки проверена командами rpm -q tcpdump и tcpdump --version. История транзакций пакетного менеджера DNF была сохранена в файл dnf.out командой dnf history > dnf.out.

3.1 К виртуальной машине был подключён дополнительный виртуальный диск /dev/sdb. На диске была создана таблица разделов GPT и один раздел /dev/sdb1, занимающий всё доступное пространство. Раздел был отформатирован в файловую систему ext4 с меткой тома MEPHI_WEB. Корректность создания файловой системы и метки проверена командами lsblk -f.
3.2 Была создана точка монтирования /mephi-web. Для автоматического подключения файловой системы при загрузке в файл /etc/fstab была добавлена запись, использующая метку тома MEPHI_WEB в качестве идентификатора файловой системы:
LABEL=MEPHI_WEB /mephi-web ext4 defaults 0 2
Корректность конфигурации была проверена командой mount -a. После этого файловая система была вручную смонтирована в каталог /mephi-web. Результат монтирования проверен командой findmnt /mephi-web

4.1 Веб-сервер nginx был запущен с помощью systemctl и добавлен в автозагрузку. Состояние сервиса проверено командами systemctl is-active nginx и systemctl is-enabled nginx.
4.2 Для анализа журналов использовалась утилита journalctl. Все сообщения, относящиеся к сервису nginx в рамках текущей загрузки системы, были сохранены в файл journalctl.out командой journalctl -u nginx -b > journalctl.out.

5.1 Для организации дискреционного управления доступом была создана группа разработчиков mephi-dev, в которую включены пользователи user1, user2 и user3 с UID 5501, 5502 и 5503 соответственно. Для кураторов создана группа curators с GID 4444, содержащая пользователей curator1 и curator2.
Каталог проекта /data/mephi-2026 принадлежит группе mephi-dev. На каталоге установлен бит setgid, благодаря чему все создаваемые внутри объекты наследуют группу проекта. Для автоматического назначения прав новым файлам и каталогам настроены default ACL. Разработчики имеют права чтения и записи, кураторы — только чтения, а остальные пользователи доступа не имеют.
Корректность настройки проверена созданием файла от имени user1, его изменением пользователями user2 и user3, чтением от имени curator1 и попыткой модификации от имени куратора, которая завершилась отказом в доступе.
5.2 Для запуска tcpdump непривилегированным пользователем вместо механизма set-UID были использованы Linux capabilities. С исполняемого файла был снят бит set-UID, после чего ему были назначены capabilities CAP_NET_RAW и CAP_NET_ADMIN. Наличие установленных привилегий было проверено командой getcap. После настройки пользователь user1 смог выполнить захват сетевого трафика без получения полномочий суперпользователя.
5.3 Проверено состояние SELinux — система работает в режиме Enforcing. Поскольку веб-сервер nginx настроен на обслуживание файлов из нестандартного каталога /mephi-web, для данного каталога было создано постоянное правило SELinux-контекста типа httpd_sys_content_t с помощью semanage fcontext. После применения контекста командой restorecon nginx получил разрешение на чтение файлов данного каталога в соответствии с политикой SELinux. Конфигурация nginx была изменена таким образом, чтобы корневая директория веб-сервера указывала на /mephi-web. Корректность настройки проверена командой curl http://localhost/.

6.1 Для ограничения локального входа кураторов был использован PAM-модуль pam_access. В конфигурацию /etc/pam.d/login добавлено правило account required pam_access.so. В файле /etc/security/access.conf группе curators был запрещён локальный вход с использованием правила - : (curators) : LOCAL, при этом для остальных пользователей вход оставлен разрешённым. Корректность настройки проверена попыткой входа через локальную консоль: пользователь curator1 войти не смог, а остальные пользователи сохранили возможность входа.
6.2 Для ограничения срока действия паролей параметр PASS_MAX_DAYS в /etc/login.defs установлен равным 90 дням. Для ранее созданных пользователей срок действия пароля настроен командой chage -M 90. Минимальная длина пароля установлена равной 12 символам с помощью параметра minlen = 12 в файле /etc/security/pwquality.conf. Корректность настроек проверена командами chage -l и попыткой установки пароля недостаточной длины.
